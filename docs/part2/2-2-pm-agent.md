## [도입] PM 에이전트가 뭐예요?

### 상황을 그려볼게요

**Q. 옆 부서 팀장이 메신저로 물어봐요:**

> "TW 팀 매뉴얼 작업, 지금 어디까지 됐어?"

평소엔 어떻게 답하시나요?

1. 공유 폴더 열어요
2. 작업자별 폴더 하나하나 클릭
3. 안에 어떤 파일이 있는지 보고 단계 추론
4. 머릿속으로 정리해서 답장

**시간이 꽤 걸려요.** 그리고 얼마 뒤에 또 다른 사람이 같은 질문을 하죠. 또 몇 분.

### PM 에이전트가 있다면

```
You: 지금 매뉴얼 작업 어디까지 됐어?

PM 에이전트:
- RFM(S): NX-Interferom v1 → 3단계 (Feedback 진행 중)
- RFM(N): AFM module → 2단계 (1st Draft 작업 중)
- RFM(K): Calibration → 4단계 (Final Review 대기)
- RFM(M): 작업 없음
- RFM(B): Manual update → 5단계 (배포 완료, LOM 이동)
```

**30초.** 그것도 항상 정확.

### 이게 에이전트예요

**에이전트 = 특정 역할을 잘 하는 AI에 역할을 부여한 거예요.** 오늘 우리가 만들 두 에이전트 중 첫 번째가 바로 이 **PM 에이전트**예요.

PM 에이전트가 잘 하는 일:
- ✅ 회사 폴더를 들여다보고 진행 상황 파악
- ✅ 내가 지시한 규칙대로 단계 자동 판정
- ✅ 사람 말로 묻기만 하면 정리된 보고서로 답변

> 💡 **오늘 워크숍 톤 알림**: 우리는 "회사 전체에 깔리는 자동 감시 시스템"을 만들지 않아요. **"클로드 코드로 이런 방향까지 가능하다"** 를 4시간에 체험하는 게 목표예요. 실제 회사 도입은 본인 IT팀과 별도 프로젝트로 가야 해요.

## [실습] PM 에이전트 만들기 — 5단계

### Step 1. 작업 폴더 확인

`parksystems-workshop/4_PM에이전트/` 폴더로 이동하세요. (3번 파일 정리에서 만든 RFM 구조를 미리 정리해둔 버전이에요.)

```
cd ~/Desktop/parksystems-workshop/4_PM에이전트
claude
```
> Windows: `cd C:\Users\USER\Desktop\parksystems-workshop\4_PM에이전트`

Nimbalyst에서도 같은 폴더 열어두세요.

폴더 구조:

```
4_PM에이전트/
  └── RFM/
        ├── RFM(S)/
        │     ├── raw data/        ← 1단계 자료
        │     ├── working/         ← 2단계 (또는 4단계) pdf
        │     └── feedback/        ← 3단계 pdf
        ├── RFM(N)/   (같은 구조)
        ├── RFM(K)/
        ├── RFM(M)/
        ├── RFM(B)/
        └── LOM/                    ← 5단계 배포 완료
```

각 폴더 안에 몇 개 더미 파일이 들어 있어요. 이게 PM 에이전트가 들여다볼 작업장이에요.

### Step 2. PM 에이전트 만들기 — `.claude/agents/PM.md`

에이전트에게 **"너는 어떤 역할이고, 어떤 규칙으로 일해"** 를 알려줘야 해요. 이걸 적은 파일이 에이전트의 **소개서**가 돼요.

클로드 코드에 이렇게 입력하세요:

```
.claude/agents/PM.md 파일을 새로 만들어줘.

내용은 이렇게:

---
name: PM
description: TW 팀 매뉴얼 작업 진행 상황을 RFM 폴더를 들여다보고 5단계로 보고하는 PM 에이전트
---

당신은 파크시스템스 TW 팀의 PM 에이전트예요.

## 당신의 일

RFM/ 폴더를 들여다보고, 작업자별로 지금 어느 단계에 있는지 보고합니다.

## 5단계 정의

1단계: 자료 취합, 교육/장비 확인, 일정/Scope 설정
2단계: 1st Draft 작업, 추가 필요 자료·협력 파악
3단계: Draft 보완 및 Review/Feedback/Revision Loop
4단계: Final Review (종료 또는 일정/Scope 조정)
5단계: Next Revision Plan & Data Backup & Release

## 폴더 변화로 단계를 판정하는 규칙

- RFM(작업자)/raw data/ 에 파일이 있으면 → 1단계
- RFM(작업자)/working/ 에 pdf가 있으면 → 2단계
- RFM(작업자)/feedback/ 에 pdf가 있으면 → 3단계
- RFM(작업자)/working/ 의 pdf 이름 앞에 (작업자) 표시가 떨어지면 → 4단계
- RFM(작업자)/ 가 비고 LOM/ 에 파일이 이동되면 → 5단계

## 보고 형식

- 작업자별로 한 줄
- "RFM(X): 프로젝트명 → N단계 (간단한 상태)" 형식
- 모르면 추측하지 말고 "확인 불가"라고 답하기
```

**Enter 누르세요.** Nimbalyst를 보면 `.claude/agents/PM.md` 파일이 새로 생기는 게 보일 거예요.

> 💡 **방금 무슨 일이?** 우리는 코드 한 줄 안 썼어요. 자연어로 "PM 에이전트는 이런 역할이야"를 적었을 뿐인데, 클로드 코드가 파일로 저장했고 이제 이 에이전트를 호출할 수 있어요.

### Step 3. PM 에이전트 부르는 명령 만들기 — `.claude/commands/progress.md`

에이전트를 매번 길게 호출하는 건 귀찮아요. **`/progress`** 같은 짧은 슬래시 커맨드로 부를 수 있게 만들어볼게요.

```
.claude/commands/progress.md 파일을 새로 만들어줘.

내용은 이렇게:

---
description: PM 에이전트를 불러서 지금 매뉴얼 작업 진행 상황을 보고받기
---

PM 에이전트를 호출해서, RFM/ 폴더의 현재 진행 상황을 5단계 규칙으로 분석해서 보고해줘.

작업자별로 한 줄씩 정리하고, 마지막에 "총 N건, 단계별 분포: 1단계 X건 / 2단계 Y건..." 식의 요약도 붙여줘.
```

이제 클로드 코드에서 `/progress` 만 치면 PM 에이전트가 호출돼요.

### Step 4. PM 에이전트 호출 — 첫 보고 받기

대화창에 입력:

```
/progress
```

PM 에이전트가 일하는 모습을 보세요. 클로드 코드가:

1. `.claude/commands/progress.md` 를 읽고 → 이게 무슨 명령인지 파악
2. `.claude/agents/PM.md` 를 읽고 → PM 에이전트 소개서 불러오기
3. `RFM/` 폴더를 하나씩 둘러봄 → 작업자별 단계 판정
4. 정리된 보고서로 답변

**기대 결과** (예시):

```
파크시스템스 TW 팀 매뉴얼 진행 상황

- RFM(S): NX-Interferom v1 → 3단계 (feedback/ 에 review pdf 있음)
- RFM(N): AFM module draft → 2단계 (working/ 에 draft pdf)
- RFM(K): Calibration spec → 4단계 (working/ 의 pdf에서 (K) 표시 떨어짐)
- RFM(M): 진행 자료 없음
- RFM(B): Manual update → 5단계 (LOM/ 으로 이동됨)

총 4건 진행 중 / 1건 휴면
단계별 분포: 2단계 1건 / 3단계 1건 / 4단계 1건 / 5단계 1건
```

> 🎉 **방금 만든 게 진짜 에이전트**예요. 옆 부서 팀장이 또 물어봐도 `/progress` 한 줄로 끝.

**응용 2. 주간 보고 형식으로**

양식 참고: 4_PM에이전트/Weekly_Report_Sample.pptx
(이 파일의 표 형식·섹션 구성 그대로 따라주세요)

```
지난 주에 가장 많이 변경된 작업자 폴더를 찾아서 알려줘. 그 팀이 가장 바쁜 팀이야.
```

> 💡 에이전트에게 추가 명령을 줄 때마다 Nimbalyst에서 파일 변화·분석 과정을 볼 수 있어요. 어떤 작업이 어떻게 진행되는지 투명하게 보여요.

## [개념] 하네스 — 에이전트 주변의 운영 시스템

방금 우리는 PM 에이전트를 만들었어요. 그런데 잘 보면 에이전트 하나만 만든 게 아니에요.

**우리가 만든 것들:**

| 파일 | 역할 |
|---|---|
| `.claude/agents/PM.md` | **에이전트 (PM 에이전트 소개서)** |
| `.claude/commands/progress.md` | 에이전트 부르는 슬래시 커맨드 |
| `RFM/` 폴더 구조 | 에이전트가 들여다보는 작업장 |
| 보고 형식 약속 | 에이전트가 답할 때의 규칙 |

이렇게 **에이전트 주변에 있는 모든 것들 — 폴더 구조·커맨드·규칙·약속** 을 통틀어 **하네스(Harness)** 라고 불러요.

쉽게 말하면:

> **에이전트 = AI에게 특정 역할을 부여한 일꾼**
> **하네스 = 에이전트가 일 잘 하게 만드는 회사 운영 시스템**
> (어떤 문서가 어디에 있고, 어떤 호출을 받으면 뭘 하는지, 결과는 어떻게 보고하는지의 규칙)

에이전트가 일을 잘 하려면 **AI 모델 자체의 능력**도 좋아야 하지만, 그만큼이나 **주변 환경(하네스)** 이 잘 정리되어 있어야 해요.

> 📚 더 깊이 알고 싶으면 부록 11 "에이전트 & 하네스 깊이"를 봐주세요. 본 수업에서는 이 정도만!

## [응용] 본인 회사 폴더에 PM 에이전트 쓰려면?

워크숍이 끝난 후 본인 프로젝트에 적용하고 싶으시다면, 이렇게 시작하시면 돼요.

**Step 1.** 본인 프로젝트 폴더로 이동:
```
cd ~/Desktop/내프로젝트
claude
```

**Step 2.** 첫 명령으로 폴더 구조부터 보여달라고:
```
이 폴더의 구조와 파일 종류를 보여주고, 어떤 일이 진행 중인지 추측해줘.
```

**Step 3.** 본인 회사의 진행 단계 규칙을 자연어로 알려주고 PM 에이전트를 만들기:
```
우리 팀은 [단계 1: ... / 단계 2: ... / ...] 식으로 작업을 진행해.
이 폴더 안에서 [어떤 신호로 각 단계를 판정할지] 정해서
.claude/agents/PM.md 에 PM 에이전트 소개서를 만들어줘.
```

→ 오늘 우리가 한 것과 똑같은 패턴이에요. 회사 폴더 구조·단계 규칙만 본인 회사에 맞게 바꿔주시면 됩니다.

**한 가지 주의**: 회사 보안 정책상 중앙 문서함을 직접 접근하기 어려울 수 있어요. 그럴 땐 부서 NAS 또는 본인 PC의 동기화 폴더부터 시작하시면 안전해요.
