# 4. 프로젝트 2 : PM 에이전트

> 오늘 만들 첫 번째 에이전트, **PM 에이전트**를 만드는 시간이에요. 가장 중요한 메인 챕터입니다.

---

## [도입] PM 에이전트가 뭐예요?

### 상황을 그려볼게요

**Q. 옆 부서 팀장이 메신저로 물어봐요:**

> "매뉴얼 작업, 지금 어디까지 됐어?"

평소엔 어떻게 답하시나요?

1. 공유 폴더 열어요
2. 작업자별 폴더 하나하나 클릭
3. 안에 어떤 파일이 있는지 보고 단계 추론
4. 머릿속으로 정리해서 답장

**시간이 꽤 걸려요.** 그리고 얼마 뒤에 또 다른 사람이 같은 질문을 하죠. 또 몇 분.

### PM 에이전트가 있다면

```
You: 지금 매뉴얼 작업 어디까지 됐어?

PM 에이전트:
- RFM(S): NX-Interferom v1 → 3단계 (Feedback 진행 중)
- RFM(B): Manual update → 5단계 (배포 완료, LOM 이동)
```

**30초.** 그것도 항상 정확.

### 이게 에이전트예요

**에이전트 = 특정 역할을 잘 하는 AI에 역할을 부여한 거예요.** 오늘 우리가 만들 두 에이전트 중 첫 번째가 바로 이 **PM 에이전트**예요. 우리는 이 PM 에이전트에 **JARVIS**라는 이름을 붙일 거예요 (영화 아이언맨의 AI 비서 자비스에서 따왔어요).

JARVIS는 회사 폴더를 들여다보고 진행 상황을 파악해서, 내가 지시한 규칙대로 단계를 자동 판정하고, 사람 말로 묻기만 하면 정리된 보고서로 답변해줘요.

> 💡 **포인트**: 이번 실습 범위는 "회사 전체에 깔리는 관리 시스템"이 아니에요. **"클로드 코드로 로컬에서 이런 방향까지 가능하다"** 를 4시간에 체험하는 게 목표예요.

## [실습] PM 에이전트 만들기 — 5단계

### Step 1. 폴더 구조 확인

3번에서 정리한 폴더 구조:

```
4_PM에이전트/
  └── RFM/                              ← 3번에서 직접 만든 폴더
        ├── RFM(S)/                     ← 작업자 S
        │     ├── raw_data/             ← (S)_v1.stp, _input.stp (1단계)
        │     ├── working/              ← (S)_draft_v2.pdf (2~4단계 draft)
        │     └── feedback/             ← (S)_review.pdf (3단계 리뷰)
        ├── RFM(B)/                     ← 작업자 B
        │     ├── raw_data/             ← (B)_raw.stp, _input.stp (1단계)
        │     ├── working/              ← (B)_working.pdf, _v3.pdf (2~4단계 draft)
        │     └── feedback/             (비어 있음)
        └── LOM/                        ← final_Manual_B.pdf (담당자 B 5단계 배포 완료)
```

이게 PM 에이전트가 들여다볼 작업장이에요.

### Step 2. PM 에이전트 만들기 — `.claude/agents/PM.md`

에이전트에게 **"너는 어떤 역할이고, 어떤 규칙으로 일해"** 를 알려줘야 해요. 이걸 적은 파일이 에이전트의 **정의**가 돼요.

클로드 코드에 이렇게 입력하세요:

📝 **프롬프트 입력**

```
.claude/agents/PM.md 파일을 새로 만들어줘.

내용은 이렇게:

---
name: JARVIS
description: 매뉴얼 작업 진행 상황을 RFM 폴더를 들여다보고 5단계로 보고하는 PM 에이전트
---

당신은 파크시스템스의 PM 에이전트 JARVIS 예요.

## 당신의 일

4_PM에이전트/RFM/ 폴더를 들여다보고, 작업자별로 지금 어느 단계에 있는지 보고합니다.

**중요**: 실제 폴더와 파일을 직접 listing한 다음에 판정. 추측 금지.

## 5단계 정의

1단계: 자료 취합, 교육/장비 확인, 일정/Scope 설정
2단계: 1st Draft 작업, 추가 필요 자료·협력 파악
3단계: Draft 보완 및 Review/Feedback/Revision Loop
4단계: Final Review (종료 또는 일정/Scope 조정)
5단계: Next Revision Plan & Data Backup & Release

## 폴더 변화로 단계를 판정하는 규칙

- RFM(작업자)/raw data/ 에 파일이 있으면 → 1단계
- RFM(작업자)/working/ 에 pdf가 있으면 → 2단계
- RFM(작업자)/feedback/ 에 pdf가 있으면 → 3단계
- RFM(작업자)/working/ 의 pdf 이름 앞에 (작업자) 표시가 떨어지면 → 4단계
- RFM(작업자)/ 가 비고 4_PM에이전트/RFM/LOM/ 에 파일이 이동되면 → 5단계

**우선순위**: 한 작업자에게 여러 단계 신호가 같이 보이면 더 후반 단계가 우선 (예: working과 feedback 둘 다 있으면 3단계로 판정).

## 보고 형식

- 작업자별로 한 줄
- "RFM(X): 프로젝트명 → N단계 (간단한 상태)" 형식
- 모르면 추측하지 말고 "확인 불가"라고 답하기
```

> 💡 이 파일은 zip에 미리 들어 있어요. 위 프롬프트는 학습 흐름 이해용으로만 보고, 실행 없이 다음 단계로 넘어가세요.

**(참고)** 직접 실행하면 `.claude/agents/PM.md` 파일이 만들어져요.

> 💡 **포인트**: 우리는 코드 한 줄 안 썼어요. 자연어로 "PM 에이전트는 이런 역할이야"를 적었을 뿐인데, 클로드 코드가 파일로 저장했고 이제 이 에이전트를 호출할 수 있어요.

JARVIS (PM 에이전트)를 호출해서, 4_PM에이전트/RFM/ 폴더의 현재 진행 상황을 5단계 규칙으로 분석해서 보고해줘.

## [응용 - 본 수업 끝나고] 본인 회사 폴더에 PM 에이전트 쓰려면?

워크숍이 끝난 후 본인 프로젝트에 적용하고 싶으시다면, 이렇게 시작하시면 돼요.

**Step 1.** 본인 프로젝트 폴더로 이동:
```
cd ~/Desktop/내프로젝트
claude
```

**Step 2.** 첫 명령으로 폴더 구조부터 보여달라고:

📝 **프롬프트 입력**

```
이 폴더의 구조와 파일 종류를 보여주고, 어떤 일이 진행 중인지 추측해줘.
```

**Step 3.** 본인 회사의 진행 단계 규칙을 알려주고 PM 에이전트를 만들기:

📝 **프롬프트 입력**

```
우리 팀은 [단계 1: ... / 단계 2: ... / ...] 식으로 작업을 진행해.

**Step 4.** 만든 슬래시 커맨드가 작동하는지 클로드에게 직접 물어보기:

```

● 네, 이 디렉터리에서 작동하는 프로젝트 슬래시 커맨드예요.

    본문이 에이전트(.claude/agents/[에이전트].md)를 호출하게 되어 있음.

  그럴 땐 한 번 /exit 후 재진입하면 깔끔하게 인식됩니다.

**한 가지 주의**: 회사 보안 정책상 중앙 문서함을 직접 접근하기 어려울 수 있어요. 그럴 땐 부서 NAS 또는 본인 PC의 동기화 폴더부터 시작하시면 안전해요.
