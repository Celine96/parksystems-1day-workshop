# 7. 프로젝트 5 : HTML 변환 (+프롬프트 핑퐁으로 디자인 개선)

> 우리가 만든 매뉴얼을 누구나 볼 수 있는 **웹페이지 형태**로 변환해보는 시간이에요.

---

## [실습] publish-manual 슬래시 커맨드 만들기

매뉴얼을 자주 HTML로 바꿀 거니 슬래시 커맨드로 만들어둘게요.

대화창에 입력:

📝 **프롬프트 입력**

```
.claude/commands/publish-manual.md 파일을 새로 만들어줘.

내용은 이렇게:

---
description: 매뉴얼 .md 파일을 보기 좋은 HTML 페이지로 변환하기
---

사용자가 .md 파일 경로를 주면, 다음 스타일로 HTML로 변환해서 같은 폴더에 저장해줘:

- 회사 매뉴얼 톤 (격식 있는 영문 페이지 느낌)
- 챕터 제목 강조 (h1, h2 스타일)
- 본문 가독성 좋은 폰트·줄 간격
- 표·코드 블록 깔끔하게
- 모바일 반응형
- 인쇄해도 깔끔하도록 print CSS 포함

저장 파일명: 원본.md 와 같은 이름의 .html
```

> 💡 이 파일은 zip에 미리 들어 있어요. 위 프롬프트는 학습 흐름 이해용으로만 보고, 실행 없이 다음 단계로 넘어가세요.

**(참고)** 직접 실행하면 `.claude/commands/publish-manual.md` 파일이 만들어져요.

이제 `/publish-manual [파일 경로]` 한 줄로 **로컬 HTML 파일** 변환 가능. (같은 폴더에 `.html` 파일이 생기고, 브라우저에서 더블클릭으로 열어볼 수 있어요.)

> 변환된 HTML을 어떻게 보고 공유할지 두 가지 방법이 있어요. 본인 상황에 맞게 진행하세요.

## 로컬에서 보기 — 본인 컴퓨터에서만

가장 단순한 방법.

📝 **프롬프트 입력**

```
/publish-manual 5_매뉴얼/output/Chapter1_Intro.md
```

<SectionTitle icon="💬" title="클로드 코드는 이렇게 답해요" sub="HTML 변환 결과" />

```
● HTML 변환 완료. 저장 위치: 5_매뉴얼/output/Chapter1_Intro.html

  적용된 스타일
  - 격식 톤 — Park Systems 매뉴얼 느낌의 네이비 액센트(#003a70), 본문 justify 정렬,
    사이드 라벨("Chapter 1 / General Information")
  - 챕터 헤더 — 큰 챕터 번호 + 서브타이틀 2단 구성, 액센트 룰 라인
  - 본문 가독성 — Helvetica/Pretendard 폴백, line-height 1.7, 880px 페이퍼 폭, 패딩 넉넉
  - 인용 표시 — [1] [2]를 <sup>로 윗첨자 처리, References 섹션은 hanging indent
  - Figure 자리 — 점선 박스 placeholder + 캡션
  - 표·코드 블록 — 액센트 컬러 좌측 보더, 호버 효과 포함
  - 모바일 반응형 — 720px 이하에서 패딩 축소·정렬 좌측·폰트 크기 조정
  - 인쇄 CSS — @page 마진, 컬러 흑백 변환, 링크 URL 자동 출력,
    page-break 제어, 푸터 고정

  브라우저에서 바로 열거나 PDF로 인쇄하면 양쪽 다 깔끔하게 나옵니다.
  다음 챕터도 같은 스타일로 변환할 수 있어요.
```

생성된 `Chapter1_Intro.html` 파일을 파일 탐색기에서 **더블클릭** 하세요. 기본 브라우저에서 깔끔한 웹페이지로 열려요.

> 💡 **포인트**: 본인이 빠르게 확인하기 좋아요. **다른 사람에게 공유**할 때는 브라우저에서 PDF로 인쇄(`Ctrl + P` → "PDF로 저장")해서 PDF로 보내면 깔끔해요. (`.html` 파일 직접 첨부는 회사 메일 보안에 차단될 수 있어요.)

## 인터넷에 띄우기 — Cloudflare Pages (URL로 공유)

로컬 HTML이 아닌 외부 URL 호스팅 하는 방법. **가입 1회 + 폴더 드래그**로 1~2분 안에 가능해요.

> ⚠️ **주의**: 회사 내부 매뉴얼·고객 정보가 들어간 자료는 **외부 호스팅 X**. 공개해도 되는 자료(일반 교육·공개 안전 가이드·포트폴리오 등)에만 사용하세요.

### 준비

- Cloudflare 계정 가입·로그인 — https://dash.cloudflare.com/sign-up (이메일 한 줄)
- 배포할 폴더 안에 **`index.html`이 있어야 해요** (Cloudflare가 자동 진입점으로 사용).

> 💡 우리는 `Chapter1_Intro.html` 만 있죠. 클로드한테 한 줄로 부탁하세요:
>
> 📝 **프롬프트 입력**
>
> ```
> 5_매뉴얼/output/Chapter1_Intro.html 을 index.html 이름으로 복사해줘.
> ```

### Step 1. 좌측 사이드바: **Build → Compute**

"Workers & Pages" 화면이 열려요.

### Step 2. 우측 상단: **Create application** 클릭

### Step 3. 상단 탭에서 **Pages** 선택

> ⚠️ 기본값이 **Workers**라 그냥 진행하면 `*.workers.dev` URL이 만들어지면서 404가 떠요. 반드시 **Pages 탭을 먼저 클릭**.

### Step 4. **"Drag and drop your files"** 선택

> ("Import an existing Git repository" 메뉴도 있지만 무시)

### Step 5. 프로젝트명 입력

- **영문 소문자 + 하이픈** (예: `nx-interferom-manual`)
- 이 이름이 그대로 URL이 돼요.

### Step 6. **Upload your project assets:** 에 `output` 폴더 드래그 업로드 → **Deploy site** 클릭

- 10~30초 후 "Next steps" 화면이 뜨면 성공
- 좌측 상단 프로젝트 이름 클릭 → 라이브 URL 확인
- URL 형식: `https://{프로젝트명}.pages.dev/`

> 💡 **포인트**: 무료 + 본인 도메인 연결 가능.

## [응용] 프롬프트 핑퐁으로 디자인 개선

`5_매뉴얼/형식/매뉴얼 형식_Intro.png` 가 우리가 원하는 포맷의 Intro 였죠. **프롬프트 핑퐁**으로 디자인을 개선해볼게요.

![우리가 목표로 하는 매뉴얼 Intro 형식](/images/manual-format-intro.png)

> 💡 실무에서는 보통 **3번 정도 핑퐁**으로 완성도가 올라요. 한 번에 완벽한 디자인은 어려우니, 비교 → 개선사항 도출 → 재생성 흐름을 익혀두세요.

📝 **프롬프트 입력**

```
디자인 프롬프트 개선 검토 : 최종 결과물이 [해당 이미지 폴더에서 드래그] 입니다.
output 결과물과 비교해서 디자인 프롬프트를 개선해주세요.
그리고 개선 프롬프트로 Chapter1_Intro.md를 다시 변환해서 index.html에 적용해주세요.
```

> 💡 **Image 드래그**: 클로드 코드 대화창에 `5_매뉴얼/형식/매뉴얼 형식_Intro.png` 를 드래그앤드롭하면 자동으로 첨부됩니다.

<SectionTitle icon="💬" title="클로드 코드는 이렇게 답해요" sub="비교 → 변경 항목 표 + 프롬프트 개선 포인트" spacious />

```
● 개선된 프롬프트로 HTML 재생성 완료. 적용된 핵심 변경은 아래 표 참고. 그 다음에 프롬프트 자체 개선 포인트도 정리.
```

**적용된 핵심 변경 (타겟 매칭)**

| 변경 항목 | Before → After |
|---|---|
| 챕터 헤더 | "Chapter 1" eyebrow + 큰 타이틀 → "Chapter 1" / "General Information" 같은 굵기 30px bold 2줄 |
| 하단 라인 | 네이비 더블라인 → 제거 |
| 컬러 시스템 | 네이비 액센트 #003B5C 곳곳 → 완전 흑백 (검정 단색만) |
| 섹션 레이아웃 | 풀너비 h2 + bottom border → CSS Grid 2단 (24% 좌측 사이드 / 76% 본문) |
| 본문 크기 | 17px → 14.5px (정보 밀도↑) |
| 인용 [1] [2] | 네이비 + 밑줄 → 검정, 밑줄 없음 |
| Figure | 점선 박스 placeholder → 연한 회색 사각형 (4:3 비율) + sans-serif 캡션 |
| 푸터 | 3열 (doc-id / date / page-no) → 2열 (doc-id date / 29) |
| 페이지 배경 | 베이지 틴트 + 카드 그림자 → 순백, 그림자 없음 |
| 챕터→섹션 간격 | 56px → 130px (타겟의 넓은 여백 재현) |

**프롬프트 자체 개선 포인트**

기존 프롬프트는 "회사 매뉴얼 톤", "가독성 좋은 폰트" 같은 추상적 형용사 중심이었어요. 새 프롬프트는:

1. **레퍼런스 이미지를 직접 지목** (`5_매뉴얼/형식/매뉴얼 형식_Intro.png`)
2. **수치 기반 스펙** — 폰트 크기, 컬럼 비율, 여백 px 명시
3. **컬러는 "흑백만" 단언적 금지** — 액센트 컬러 사용 금지 명시
4. **레이아웃 구조 명시** — "2단 grid, 좌측 22-25%"
5. **안티패턴 섹션 추가** — "네이비 사용 금지", "Introduction을 풀너비 h2로 배치 금지" 같은 부정형 가이드

부정형 가이드(~하지 말 것)가 들어가니 LLM이 디폴트 디자인 본능에서 벗어나기 쉬워졌어요.

> 💡 **포인트**: **부정형 가이드** ("~하지 말 것")가 LLM을 디폴트 본능에서 벗어나게 해요. "깔끔하게" 같은 추상적 형용사 대신 **레퍼런스 이미지 + 수치 + 금지 사항** 조합으로.

<SectionTitle icon="👀" title="열어서 결과 확인" sub="이전 디자인 vs 새 디자인 비교" />

📝 **프롬프트 입력**

```
방금 디자인 재작업한 index.html을 기본 브라우저에서 열어줘.
```

→ 새 디자인이 적용된 페이지가 브라우저에서 열려요. 이전 디자인과 한눈에 비교해보세요.

> 💡 **Cloudflare에 배포 중이라면**: Cloudflare Pages의 해당 프로젝트에서 `output` 폴더를 다시 드래그 업로드하면 **라이브 URL도 즉시 갱신**돼요.
